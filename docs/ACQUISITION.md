규칙은 아이디어가 아니라 **겪은 사고의 기록**이다.

| 축적된 것 | 실측 |
|---|---|
| 판정 함수 | **16개** |
| 이름 붙은 규칙 상수 | **120개** |
| 거절 경로(이 글은 후기가 아니다라고 판정하는 지점) | **81개** |
| 판정 엔진 | **2,854줄** — 그중 **주석이 1,436줄(50%)** |
| 품질 엔진 전체(핵심 4파일) | **5,092줄** |

| 협업 기록(coordination#) | **37건** |
| 룰갭 제안 | **59건** |
| **근거로 인용된 실제 오염 사례**(카페 id) | **241곳** |
| 날짜가 박힌 수리 이력 | **111개 날짜** |

**코드 절반이 "왜 이 규칙이 있는지"를 적은 주석이다.** 예: 카페 상호에 '커피'가 들어가면 광고 필터가 꺼지는
결함이 있었다(공개 카페의 30%, 14,633곳 해당). 그런 것은 **겪지 않으면 알 수 없다.**
123건의 의사결정과 241곳의 실제 사고를 단기간에 만들 수는 없다.

## 4. 받아서 돌릴 수 있는가

| 항목 | 상태 |
|---|---|
| 코드 규모 | lib 모듈 **106개** · 라우트 **138개** · 화면 **41개** |
| DB 스키마 | `web/db/schema.sql` — 테이블 99 · 컬럼 835 · 인덱스 151 · 제약 112 |
| 필요한 환경변수 | `web/.env.example` — **키 110개** |
| 자율 조직 | `agents/` — 러너 **39** · 에이전트 헌법 **28** · launchd 템플릿 **24** |
| 조직 설치 | `agents/launchd/install.sh` — 저장소 위치 자동 인식. **현재 등재 14개와 완전 일치 확인** |
| 배포 관문 | `npm run ship` = preflight → fixtures → build → color:check → smoke → push |

```bash
psql "$DATABASE_URL" -f web/db/schema.sql     # ① 스키마(구조만)
cp web/.env.example web/.env.local            # ② 환경변수 채우기
cd web && npm ci && npm run preflight         # ③ 검증(컬럼·인덱스·테스트 72건·sql 912개)
./agents/launchd/install.sh --dry-run         # ④ 조직 설치 예행
```

### 양수인이 알아야 하는 제약

1. **자율 조직은 macOS 전용**(launchd). 리눅스로 옮기려면 같은 스케줄로 cron/systemd를 만들면 된다 —
   스케줄은 각 `agents/launchd/*.tmpl`의 `StartCalendarInterval`에 그대로 적혀 있다.
2. **LLM 에이전트는 구독 기반 `claude -p`로 돈다.** 양수인은 자기 콘솔 키로 바꾸면 된다 —
   **양도 불가가 아니라 운영비가 생긴다.** ⚠️ 구독 토큰을 서버에서 쓰면 ToS 위반이다.
3. **후기 원본은 네이버 블로그·카페 검색 API에서 온다**(출처 필드 100% 기록). 네이버 오픈API 약관 7.3.③은
   **지역정보**(상호·주소·좌표)를 별도 DB로 관리하는 것을 금지한다. 지역정보는 공공 인허가 원장(data.go.kr)
   매칭이 **22,616/48,744곳(46.4%)**이고, 일원화하면 그 제약이 사라진다. 위반 시 약관상 제재는
   **API키 정지**뿐이다(벌금·손배 조항 없음). **DB를 넘기지 않고 코드+재수집으로 넘기는 구조도 가능하다** —
   그 경우 복제 불가분(52.7%)은 양수인이 다시 갖지 못한다는 점을 가격에 반영해야 한다.
4. **인프라는 Vercel + Neon 공용 계정**에 5개 서비스가 함께 있다. 분리 이전이 필요하다.

## 5. 품질을 어떻게 증명하는가

주장이 아니라 **매 배포마다 기계가 검사**한다.

| 관문 | 무엇을 막는가 |
|---|---|
| `preflight` | 없는 컬럼 참조 + 뜨거운 쿼리의 인덱스 누락 (2026-08-30 전체 404 장애 재발방지) |
| **불변식 테스트 72건** | 규칙이 주석의 약속과 어긋나는 것 |
| `schema-guard` | sql 템플릿 **912개**가 실존 테이블·컬럼을 가리키는지 — **현재 결함 0** |
| `color:check` | 디자인 토큰이 안 풀려 색이 사라지는 것 |
| `smoke` | 빌드한 코드를 실제로 띄워 소비자 화면 6개(유입 99%)가 뜨는지 |
| `search-eval` | 골든 질의 28개 채점 — **2026-10-18 종합 96%**(지역 100·사실 93·상호 100·무의미질의 100) |
| `pipeline-report` | 파이프라인 7단계의 적체가 줄고 있는지(막힌 단계 탐지) |

```bash
cd web && npm run preflight && npm run build && npm run color:check && npm run smoke
node scripts/search-eval.mjs
node --import tsx scripts/pipeline-report.mjs
```

## 7. 작성자의 판단

**기술과 데이터는 넘길 수 있는 수준이다.** 복제 불가분이 절반이고, 규칙은 123건의 의사결정과 241곳의 실제
사고로 만들어졌고, 코드 절반이 그 근거를 설명한다. 품질은 매 배포마다 72개 불변식이 증명한다.
1인이 35종 자동 작업으로 운영한다 — 흔하지 않다.

**값을 매기기 어려운 이유는 품질이 아니라 매출 0이다.** 데이터를 6만 곳으로 늘려도 그 칸은 0원이다.
가치검증(사장님 139명 중 결제 0)이 먼저다.

**그래서 이 자산의 성격은 "매출을 사는 거래"가 아니라 "유통을 가진 쪽이 품질 엔진을 사는 거래"다.**
이미 트래픽이 있는 곳(지역 커뮤니티·포스·예약·프랜차이즈 본사·상권 분석)이 이 엔진과 48,744곳을
자기 유입에 붙이는 그림이 가장 현실적이다.
