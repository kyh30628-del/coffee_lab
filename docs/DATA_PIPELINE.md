# 데이터 파이프라인 & 카페 자동 발굴 에이전트

> 이 문서는 "동네 커피 노트"가 **어떻게 정확한 카페 데이터를 모으고·검증하고·계속 늘리는지** 정리한다.
> 최상위 원칙은 `PRINCIPLES.md`(헌법)·`STATUS.md`. 정확도가 생명이다.

---

## 0. 한눈에

```
발굴(discover) → 합성(synth) ─ 품질엔진(규칙+LLM) ─→ 등급/공개 → 임베딩 → 화면
   네이버 지역검색      네이버 블로그 후기 수집      검증/참고만 공개   시맨틱검색
        ▲                                                              │
        └──────────────  cron-grow 에이전트(매일 순회·재판정)  ◀────────┘
```

- **합법 소스만**: 네이버 지역검색(Place)·네이버 블로그 검색 API. 스크래핑 없음.
- **환각 금지**: 모든 숫자·등급은 수집·검증된 실제 리뷰에서만. 데이터 없으면 "발굴/비공개"로 정직 표시.
- **양이 아니라 옥석**: 수집 리뷰의 ~60%는 노이즈 → 걸러내고 검증된 것만 사용.

## 1. 발굴 (lib/discover.ts)

- **소스**: 네이버 지역검색 `local.json` (쿼리당 최대 5건, 댓글순).
- **방식**: `지역(시·군·구) × 다양한 키워드`(로스터리·스페셜티·핸드드립·동네카페·감성카페 등 20종)로 수집.
- **제외**: 대규모 저가 프랜차이즈(스타벅스·메가·컴포즈·만랩·더리터 등) + 비(非)카페(정육·약국 등).
- **중복 제외**: 이름 일치 또는 좌표 근사(±0.0005°).
- 적재: `source='discover'`, `published=false` (합성 전).
- **한계**: 네이버 플레이스에 **미등록**이거나 **네이버 블로그 글이 0**인 카페는 수집 불가
  (예: "시월의곰커피공장" — 플레이스·블로그 모두 0 → 합법 소스 없음). → **사장님 직접 등록**(/cafe/register)으로 보완.

### 1-B. 공공데이터 상가정보 발굴 (lib/sangga.ts) — 누락 최소화
- **소스**: data.go.kr 소상공인시장진흥공단 「상가(상권)정보」 — 등록 상가 중 **'커피전문점/카페/다방'만**.
  **위경도(WGS84) 직접 제공**(좌표변환 불필요·정확). 프랜차이즈·중복 제외.
- `storeListInDong`(divId=signguCd)로 시·군·구 단위 조회. METRO_SIGNGU(수도권 시군구코드) 순회.
- 네이버 지역검색이 놓치는 카페(예: 시월의곰커피공장)를 공식 데이터로 보완.
- **필요**: `DATA_GO_KR_KEY`(data.go.kr 무료 발급). 라우트 `/api/sangga-discover`는
  기본 **dry-run(미적재, 샘플 반환)** — 위경도·필터 검증 후 `apply:true`로 적재(`{all:true}`로 전 수도권).

## 2. 후기 수집 (lib/webSearchCollector.ts, placesCollector.ts, youtubeCollector.ts, synthStore.ts)

- 다중 소스: **네이버 블로그/카페글** · **구글 Places 리뷰** · **유튜브**(YouTube Data API v3).
- **유튜브**(lib/youtubeCollector.ts): 카페 영상 검색 → 영상 1개=스니펫 1개(제목+설명+상위 댓글), 출처 링크=영상 URL, 날짜=게시일. 자막/원문은 합법적으로 불가 → 제목·설명·댓글까지만. 다른 소스와 **동일한 검증 엔진**(주제성·동명·지역 필터)+Sonnet 판정 통과분만 채택. 합성 가중 1.1. 화면엔 ▶YouTube 배지+영상 링크로 표시(사실성). 필요 키: `YOUTUBE_API_KEY`(무료, 일 10,000유닛).
- 네이버 블로그/카페글 검색으로 후기 스니펫(제목+요약) 수집. 지역을 항상 포함해 다른 지점 노이즈↓.
- **display=100**(호출 수 동일=쿼터 동일, 카페당 후기 ~5배). 저작권: 원문 복제 금지 — 인용 한 줄 + 링크 + 날짜만.
- **raw 보존**: 수집 원본을 `raw_reviews`에 저장 → 재합성·재판정 시 **API 재호출 없이 재사용**(쿼터 절약·재현). `refresh:true`일 때만 새로 수집(최신성).
- **안전**: 네이버 쿼터/오류로 수집 0이면 '진짜 0건'과 구분해 **DB 미변경(보존)** → 재합성이 기존 공개 카페를 망치지 않음.
- (네이버 오픈 API 한도 25,000/일. 구글 Places는 쿼터/결제 시.)

## 3. 품질 검증 엔진 — 해자 (lib/reviewQuality.ts + reviewJudge.ts)

수집된 "리뷰의 바다"에서 옥석만 가린다. **규칙 1차 + LLM 2차**.

### 3-1. 규칙 (결정적·투명·무료)
판정: `verified(검증) / reference(참고) / rejected(탈락)` + 0~100점 + 사람이 읽는 근거.
- 제목-주제성(전체 이름 일치는 강함, 토큰만이면 '카페 맥락' 필요 — 흔한단어 오매칭 방지)
- 수도권 밖 도시 / 다른 시·군·구 → **동명·다른 지점** 배제
- 방문 단서·구체 후기 신호 가산 / 나열식 모음글·광고·해시태그도배 감점
- 카페명 0 → 탈락. 단, **이름 불명확하나 후기 맥락 뚜렷**하면 버리지 않고 `borderline`(LLM 재판정 대상).

### 3-2. LLM 재판정 (스마트·맥락)
- `borderline` 리뷰를 LLM이 **내용·맥락을 읽어** "정말 이 카페의 양질 후기인지(about) + 도움되는지(helpful)" 판정 → 양질만 살림.
- 이름이 글자 그대로 없어도 지역·컨셉·메뉴가 일치하면 살리고, 광고·무관·동명은 버림.
- **제공자 우선순위**: `ANTHROPIC_API_KEY`(Claude Haiku 4.5, 프롬프트 캐싱) → `GOOGLE_AI_KEY`/`GOOGLE_API_KEY_1`(Gemini flash-lite).
- **LLM은 판정만** 한다(데이터 생성 금지 — 환각 방지). 실패/쿼터 소진 시 **자동 폴백**(규칙 결과 유지, 무회귀).

## 4. 합성 + 저장 (lib/synthStore.ts, collectOrchestrator.ts, synthEngine.ts)

- 검증+참고(노이즈 제외) 리뷰로: 정체성·성격축(char_scores)·취향축·**리뷰 게시일(주기)**·근거후기·품질통계 산출.
- 등급: **검증(신뢰리뷰 30+) / 참고(5~30) / 발굴(5미만)**. 검증·참고면 **자동 공개**, 발굴/수집0이면 비공개(정직).
- 2-pass: 규칙 합성 → 경계 LLM 판정 → 통과분 화이트리스트로 재합성.

## 5. 임베딩 시맨틱 검색 (lib/embed.ts)

- Gemini `gemini-embedding-001`(768d)로 카페 텍스트 임베딩(pgvector) → 자연어 검색.
- cron-embed가 매일 NULL·오래된(재합성 후 stale) 임베딩을 보충(자가치유).

## 6. 자동 성장 에이전트 (app/api/cron-grow) — "정확한 카페를 계속 추출"

매일 **03:00 KST(18:00 UTC)** 1회:
1. `discovery_state`에서 **가장 오래 발굴 안 된 지역 1곳** 순회 발굴(신규 카페 적재).
2. 카페를 **미합성 우선 → 가장 오래된 순**으로 12곳 합성/재판정(`synthAndStore`).
   - 규칙+LLM으로 정확도가 회차마다 누적 상승. Gemini 쿼터 회복되면 그 회차부터 재판정 재개.
3. 검증/참고만 자동 공개. 결과는 `{discovered, synthesized, published, llmRescued, pendingNew}`.

→ 사람이 손 안 대도 **수도권 전역을 정확하게 계속 채우고 갱신**한다.

### 크론 전체
| 크론 | 주기(UTC) | 역할 |
|---|---|---|
| cron-grow | 매일 18:00 | 발굴 + 합성/재판정(성장 에이전트) |
| cron-embed | 매일 08:00 | 임베딩 보충·갱신 |
| cron-resynth | 매주 월 04:00 | 오래된 카페 재수집 |
| cron-snapshot | 매주 일 04:00 | 평점 스냅샷(모멘텀) |

## 8. 정확도 점검 체크리스트
- [ ] 새 카페가 검증/참고로 공개되려면 **교차검증된 실제 후기 5건+** 필요.
- [ ] 동명/다른 지점/무관 글은 규칙+LLM이 차단 — 의심되면 해당 카페 `synth_quality.rejectReasons` 확인.
- [ ] 네이버에 없는 카페(플레이스·블로그 0)는 수집 불가 → 사장님 등록 유도.
