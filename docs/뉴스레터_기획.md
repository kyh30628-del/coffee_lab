## 0. 확정된 결정 (사장님 승인)
| 항목 | 결정 |
|---|---|
| 수신 대상 | **활성 구독 + 활성 체험** 사장님 모두 (`subscriptions.status='active'`), 수신거부 제외 |
| 생성·발송 | **반자동** — 자동 초안 생성 → 관리자 검수·승인 → 발송 |
| 모델 | 생성 **Sonnet**(풍성함), 분류·요약 보조 Haiku 가능 |
| 주기 | 매주 **월요일 오전**(야간 발송 금지) |
| 사실·저작권 | **사장님이 직접 검토 못 함** → **에이전트가 자동 처리**, 위험 항목만 ⚠️ 플래그 |

## 1. 비용 구조 (중요·오해 금지)
- **생성비는 "회당"이다. 구독 카페 수와 무관.** 매주 1번 생성한 동일 뉴스레터를 전원에게 발송.
- 회당 추정: 웹서치+종합(Sonnet) ≈ **$0.5~1 / 주**. 발송(Resend)은 건당 거의 0원.
- 예) 구독자 500명이어도 주당 생성비는 1회분. → **구독자 늘수록 ROI↑**.
- ⚠️ 현재 **API 크레딧 소진** → 생성 실행은 소액 충전 후. (구독 토큰 안 씀.) 코드·인프라는 미리 완성해 둠.

## 2. 콘텐츠 구성 (매거진형)
1. 이번 주 한눈에 (TL;DR 3줄)
2. 📊 트렌드 레이더 — 분야별(커피/카페/디저트) 급상승 키워드 + 한 줄 (데이터 근거 지향)
3. ☕ 커피 인사이트 (1~2건 심층)
4. 🍰 디저트 스포트라이트 (핫메뉴 + 응용 팁)
5. 🔥 뜨는 카페 동향 (+ **우리 플랫폼 momentum = 독점 데이터**)
6. 💡 사장님 액션 3 (트렌드→우리 가게 적용)
7. 📰 짧은 업계 뉴스 (3~5건, 출처 링크)
8. 마무리·다음 주 예고 + **수신거부 안내**
- 모든 항목에 **"우리 가게엔?"** 한 줄 → 바로 활용.

## 3. 🤖 에이전트 아키텍처 (프로덕션 안전)
> ⚠️ claude.ai MCP(네이버 등)는 **내 작업 세션에서만** 쓰이고 배포된 앱 런타임엔 없음.
> 따라서 프로덕션 생성기는 **Anthropic API(Sonnet) + 내장 `web_search` 서버툴**로 수집·종합한다.

파이프라인(주 1회):
1. **수집·종합 (Generator)** — Claude Sonnet + `web_search` 툴. 프롬프트에 섹션 템플릿 + 우리 `momentum` 데이터 주입 → **구조화 JSON**(섹션별 항목 + 각 항목의 출처 URL) 산출. 적응적 사고(adaptive thinking).
2. **사실확인·안전 패스 (Verifier)** — 2차 LLM 패스. 각 항목 주장을 **출처 스니펫과 대조** → `verified|uncertain` 라벨. uncertain·출처없음은 **⚠️ 확인필요** 플래그.
3. **저작권·컴플라이언스 가드(결정적 규칙)** — 항목당 **요약 ≤2문장·원문 복제 금지·출처 링크 필수**, 이미지 복제 금지, 과장·의료효능 표현 차단, 광고성 표기·수신거부 삽입.
4. **관리자 검수 UI** — 미리보기(플래그 강조) → 편집/항목삭제/승인/반려.
5. **발송 (Sender)** — 활성 구독+체험, 수신거부 제외, 감성 이메일(수신거부 링크) Resend 발송 + 발송 로그.

## 4. 🛡️ 사실·저작권 안전장치 (사장님 검토 부담 최소화)
- **출처 강제**: 사실 주장엔 반드시 출처 URL. 없으면 자동 제외 또는 ⚠️.
- **요약 only**: 원문 복제 금지(항목당 ≤2문장), 항상 "출처 링크"로 원문 연결 → 저작권 안전(우리 기존 후기 인용 원칙과 동일).
- **자동 팩트체크**: Verifier가 각 주장을 출처와 대조해 `uncertain`이면 ⚠️ → 관리자에게만 표시.
- **금지 표현 결정적 차단**: 미검증 단정 통계, 의료·효능 과장, 비방 → 룰로 거른다.
- **정보통신망법(광고성)**: ① 수신 **동의**(구독/체험 가입 시 체크), ② 매 메일 **수신거부** 링크·방법, ③ 영리목적 광고성 정보 표기 검토, ④ **야간(21~08시) 발송 금지**.
- 결과: 관리자는 **⚠️ 플래그 항목만** 확인하면 됨(전문가 검토 불필요).

## 5. 데이터 모델
```sql
newsletters (
  id SERIAL PK, issue_no INT, week_of DATE,
  status TEXT DEFAULT 'draft',            -- draft|approved|sent|failed
  title TEXT, sections JSONB,             -- [{key,title,items:[{text,why,source_url,verified,flag}]}]
  flags JSONB,                            -- ⚠️ 확인필요 모음
  model TEXT, cost REAL,
  created_at, approved_at, sent_at, sent_count INT
)
newsletter_sends (id, newsletter_id, sub_id, email, status, sent_at, opened_at)
newsletter_optout (email TEXT PK, sub_id, opted_out_at)
-- subscriptions.newsletter_opt_in BOOLEAN DEFAULT true  (가입 시 수신 동의)
```
수신 대상 쿼리: `status='active'` 구독·체험 ∧ 이메일 有 ∧ optout 아님 ∧ opt_in=true.

## 6. 발송 타이밍/주기
- 매주 **월요일 08:00 KST** 자동 **초안 생성**(cron) → 관리자 승인 대기.
- 관리자 승인 시 즉시 발송(단, **21~08시 발송 금지** 가드).

## 7. 구현 로드맵
- [ ] 1. 데이터 모델(newsletters/sends/optout) + 구독 수신동의/거부 필드
- [ ] 2. Generator(lib): Sonnet+web_search → 섹션 JSON(+momentum 주입)
- [ ] 3. Verifier + 저작권/컴플라이언스 가드(결정적)
- [ ] 4. 관리자 검수 UI(생성·미리보기·편집·승인·발송)
- [ ] 5. 감성 이메일 템플릿 + 수신거부 링크/페이지
- [ ] 6. 발송(활성 구독+체험) + 발송 로그 + 옵트아웃
- [ ] 7. cron(월 08:00 초안 생성) + (확장) 오픈추적·개인화·분야 세분화

## 8. MVP (1차)
관리자 **"이번 주 뉴스레터 생성"** → 수집+종합(섹션 5개) + 자동 팩트/저작권 가드 → 미리보기(⚠️ 강조)·편집·승인 → 활성 구독+체험에 발송(+수신거부). cron·개인화는 2차.
