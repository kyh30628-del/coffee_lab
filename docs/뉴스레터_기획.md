# 구독 사장님 전용 주간 트렌드 뉴스레터 — 기획안

> 작성 2026-06-21. 구독 가치를 매주 체감시키는 리텐션·차별화 도구.
> 콘셉트: **"매주 월요일, 커피·카페·디저트 시장 흐름을 한 통에" — 사장님을 위한 산업 트렌드 큐레이션.**

---

## 1. 콘셉트 · 포지셔닝
- 분석 리포트(내 카페 숫자)가 **아님**. **시장 전체의 트렌드·키워드·핫메뉴·뜨는 카페**를 종합한 **에디토리얼 뉴스레터**.
- 분야: **☕ 커피 · 🏠 카페(공간/운영) · 🍰 디저트** 3축.
- 톤: 뉴스 발간물처럼 풍성하고 다양하게. 동네 커피 노트 감성(따뜻한 세리프).
- 가치: 사장님이 **메뉴 기획·마케팅·시즌 대응**에 바로 쓰는 "시장 감각". 혼자선 못 모으는 걸 매주 떠먹여줌 → 구독 유지 이유.
- 차별점: 남들은 못 가진 **우리 플랫폼의 검증된 '뜨는 카페' 데이터**를 트렌드 근거로 섞음.

## 2. 콘텐츠 구성 (섹션 — 매거진형)
1. **이번 주 한눈에** — 3줄 요약(TL;DR) + 이슈 번호·발행일
2. **📊 트렌드 레이더** — 분야별(커피/카페/디저트) **급상승 키워드 Top** + 한 줄 해설 *(네이버 데이터랩 검색량 근거 → "감"이 아닌 데이터)*
3. **☕ 커피 인사이트** — 원두·추출·음료 트렌드 1~2건 심층 (예: 디카페인 고급화, 산지 이슈, 시즌 음료)
4. **🍰 디저트 스포트라이트** — 요즘 뜨는 메뉴 (예: 두바이초콜릿·약과·휘낭시에·할매니얼) + 왜 뜨는지·응용 팁
5. **🔥 뜨는 카페** — **우리 플랫폼 momentum 데이터** 기반 N곳 + 뜨는 이유 (검증된 후기 모멘텀)
6. **💡 사장님 액션** — 트렌드를 우리 가게에 적용하는 실전 팁 3가지
7. **📰 짧은 업계 뉴스** — 3~5건 묶음 (한 줄 + 출처 링크)
8. **마무리 · 다음 주 예고**

> 매주 전부 채우기보다, **2·4·5·6은 고정**, 3·7은 소재 따라 가변.

## 3. 콘텐츠 소싱 파이프라인 (어떻게 풍성하게 채우나)
| 소스 | 용도 | 수단 |
|---|---|---|
| 네이버 **데이터랩** 검색어/쇼핑 트렌드 | 분야별 급상승 키워드(정량 근거) | MCP `NaverSearch-datalab_*` |
| 네이버 **블로그·뉴스·카페글** 검색 | 요즘 화제 메뉴·카페·이슈(인용·출처) | MCP `search_blog/news/cafearticle` |
| **우리 플랫폼 momentum/snapshot** | 검증된 뜨는 카페(독점 데이터) | `/api/momentum`, `cafe_snapshots` |
| **웹 검색/Claude 지식** | 글로벌·심층 트렌드, 맥락 | WebSearch/WebFetch + LLM 종합 |
| **LLM 편집** | 위 원자료를 매거진 톤으로 종합·재구성 | 생성 단계 |

흐름: **수집(데이터랩+검색+momentum) → LLM 섹션별 종합 초안 → 관리자 검수·편집 → 발송**

## 4. 생성·검수·발송 (반자동 권장)
- **주 1회**(월요일 오전) 자동 **초안 생성** → 관리자 화면에서 **미리보기·편집·승인** → **활성 구독자에게 발송**.
- 왜 반자동: 사실오류·저작권·톤·광고표현을 관리자가 최종 점검(품질·법적 안전). 익숙해지면 완전 자동 옵션.
- 인프라: vercel cron(이미 사용 중) + Resend(이미 연동) 재사용.

## 5. 데이터 모델
```
newsletters        (id, issue_no, week_of DATE, status['draft'|'approved'|'sent'],
                    title, sections JSONB, sources JSONB, created_at, approved_at, sent_at)
newsletter_sends   (id, newsletter_id, sub_id, email, sent_at, opened_at, status)
newsletter_optout  (email/sub_id, opted_out_at)   -- 수신거부(법적 필수)
```
- 수신 대상: `subscriptions.status='active'` (구독자). **체험 포함 여부 = 결정 필요**(아래).

## 6. ⚖️ 법적 체크 (반드시)
- **정보통신망법(광고성 정보)**: 뉴스레터가 서비스 홍보를 겸하면 **광고성** → ① **수신 동의**(구독/가입 시 별도 체크), ② 제목/본문에 **"(광고)" 표기 가능성 검토**, ③ **수신거부 링크·방법** 매 메일 필수, ④ 야간(21~08시) 발송 제한.
- **저작권**: 블로그·뉴스 **원문 복제 금지** → 요약 + **출처 링크**(우리 기존 인용 원칙과 동일). 이미지 직접 복제 금지.
- **사실 정확성**: 데이터랩·뉴스 등 **출처 있는 사실** 위주. Claude 단독 단정 자제.

## 7. 비용
- 주 1회 LLM 종합(수집자료 입력 + 편집 출력) ≈ 회당 수만 토큰. **월 4회로 소액**(모델·분량에 따라 추정 회당 $0.2~1).
- ⚠️ 현재 **API 크레딧 소진** 상태 → 발송 시작 시 **소액 충전 필요**. (구독 토큰은 안 씀.)

## 8. 단계별 로드맵
- [ ] **0. 결정 확정**(수신대상·자동화수준·모델·발송요일) ← 먼저
- [ ] 1. 데이터 모델(newsletters/sends/optout) + 수신동의·수신거부 필드
- [ ] 2. 수집기: 데이터랩 + 블로그/뉴스 + momentum → 원자료 묶음
- [ ] 3. LLM 종합 생성기(섹션 템플릿·출처 보존)
- [ ] 4. 관리자 검수·편집·승인 UI(미리보기)
- [ ] 5. 감성 이메일 템플릿 + 수신거부 링크
- [ ] 6. 발송(활성 구독자) + 발송 로그 + 오픈 추적(선택)
- [ ] 7. (확장) 자동 스케줄, 개인화(내 동네 동향), 분야 세분화

## 9. MVP 제안 (1차 출시)
관리자 **"이번 주 뉴스레터 생성"** 버튼 → 수집+LLM 초안(섹션 5개: 한눈에·트렌드레이더·디저트·뜨는카페·사장님액션) → **편집·승인** → 활성 구독자 발송(+수신거부). 나머지 섹션·자동화는 2차.

## 10. 결정 필요 (이걸 정하면 바로 1단계 착수)
1. **수신 대상**: 활성 구독자만 / 구독+체험 모두
2. **자동화 수준**: 반자동(관리자 검수·승인) / 완전 자동
3. **모델·비용**: 풍성함 우선(Sonnet) / 비용 우선(Haiku)
4. **발송 요일/주기**: 월요일 오전 주 1회(기본) / 기타
